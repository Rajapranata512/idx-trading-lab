# Stage 1-3 Production Foundation Runbook

This runbook covers pre-open delivery reliability, point-in-time IDX universe
freshness, and daily-price/corporate-action quality. These controls improve input
and operational reliability; they do not make Model V2 a final trading decision.

## 1. Pre-Open Delivery

GitHub Actions is the primary sender:

- `08:05 WIB`: primary run.
- `08:25 WIB`: same-platform retry.
- `scripts/preopen_delivery_guard.py` prevents a second send after a successful or
  still-active run on the same Jakarta date.
- A failed delivery attempts to send a compact Telegram failure alert.

Vercel is the independent watchdog:

- `web/vercel.json` schedules `/api/preopen-watchdog` at `01:15 UTC` on weekdays.
- The endpoint checks GitHub Actions and dispatches the workflow only when no
  successful or active delivery exists for the current Jakarta date.
- Delivery remains idempotent because the GitHub workflow guard runs again.

Required Vercel environment variables:

```text
CRON_SECRET=<random secret generated by Vercel or at least 16 bytes>
GITHUB_WATCHDOG_TOKEN=<fine-grained token with Actions read/write for this repo>
GITHUB_WATCHDOG_REPOSITORY=Rajapranata512/idx-trading-lab
GITHUB_WATCHDOG_WORKFLOW=model-v2-shadow-preopen.yml
```

`GITHUB_WATCHDOG_REPOSITORY` and `GITHUB_WATCHDOG_WORKFLOW` are optional when the
defaults remain correct. Never commit these secrets.

The sender rejects stale Model V2 shadow reports. The production limit is five
calendar days so Friday market data can still be delivered on Monday. A stale
report must be regenerated by `run-daily`; do not bypass the age gate.

### GitHub Actions Runtime

Both production workflows use Node.js 24 action generations on GitHub-hosted runners:

- `actions/checkout@v6`;
- `actions/setup-python@v6`;
- `actions/cache@v5` where Model V2 artifacts are restored.

Do not downgrade to `checkout@v4`, `setup-python@v5`, or `cache@v4`; those generations
target Node.js 20 and produce deprecation warnings. These Node.js 24 generations require
Actions Runner 2.327.1 or newer; this project uses maintained GitHub-hosted runners.

## 2. Point-In-Time IDX Universe

Tracked files:

```text
data/reference/universe_history.csv
data/reference/universe_lq45_idx30.csv
reports/universe_update_state.json
```

`universe_history.csv` stores LQ45 and IDX30 memberships with `effective_from` and
`effective_until`. `run-daily` selects the active period and enforces exactly 45
LQ45 and 30 IDX30 constituents. Missing, stale, overlapping, or malformed snapshots
block the production run.

Import an official IDX announcement ZIP:

```powershell
python -m src.cli import-idx-universe-archive `
  --archive C:\path\official-idx-announcement.zip `
  --source-document "https://www.idx.id/...official-announcement..."

python -m src.cli update-universe --force
```

The currently tracked official period is `2026-08-03` through `2026-10-30`.
Import the next official archive before `2026-10-31`; otherwise the freshness
gate intentionally blocks the pipeline.

The tracked history contains eight official periods from `2024-11-01` through
`2026-10-30`, with exactly 45 LQ45 and 30 IDX30 constituents per period. Each period
retains its official IDX archive URL. The free official archive range located for this
repository does not cover dates before `2024-11-01`, so earlier research remains an
explicit coverage gap and cannot claim survivorship-bias-safe universe membership.

Live scoring filters feature rows to the active universe. Historical model
research must use `universe_history.csv` point-in-time membership and must not
retroactively apply today's constituents to old dates.

## 3. Price And Corporate-Action Quality

The canonical raw file remains unadjusted and auditable:

```text
data/raw/prices_daily.csv
```

Every ingestion writes or refreshes:

```text
data/processed/prices_daily_adjusted.csv
reports/corporate_action_anomalies.csv
reports/price_reconciliation.json
reports/data_quality_report.json
```

Features use the adjusted file. Only confirmed `stock_split` and
`reverse_split` rows change historical OHLCV. The ratio means new shares divided
by old shares; prices before the effective date are divided by the ratio and
volume is multiplied by it.

Maintain `data/reference/corporate_actions.csv` with:

```text
ticker,effective_date,action_type,ratio,status,source
```

Use `status=confirmed` only with a traceable source. An unexplained price jump
above the configured threshold quarantines that ticker for three days and blocks
the production run while the anomaly is active.

Legitimate non-corporate market events belong in
`data/reference/verified_price_events.csv`:

```text
ticker,event_date,event_type,status,source
```

A confirmed row resolves only the exact ticker/date anomaly and never adjusts
OHLCV. For example, the GOTO jump on 2023-05-31 is annotated as an MSCI index
rebalance event with the official MSCI review document as its traceable source.

Price reconciliation compares the primary provider with an independent CSV or
yfinance. It checks recent close prices, overlap coverage, and mismatch ratio.
When EODHD is primary, set `EODHD_API_TOKEN` so yfinance remains independent. If
the primary provider falls back to yfinance, configure a separate reference CSV;
yfinance cannot reconcile against itself. Production currently warns when the
independent source is unavailable because `reconciliation_required=false`;
switch it to `true` only after a dependable secondary source is continuously
available.
